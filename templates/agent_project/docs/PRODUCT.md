# Product brief

Status: Draft until reconciled with the user's instructions.
Last updated: Fill during setup.

## Idea and audience

Describe the problem, intended users and value of the finished first version.

## Primary journey

Describe a concrete beginning-to-end journey, including failure/recovery. For a game describe
the playable loop and completion condition; for an app describe the useful user outcome.

## First complete scope

List required capabilities and finite content/platform obligations. Separate later ideas into
explicit exclusions. Define enough scope to know when the project is finished.

## Invariants and constraints

Record rules the agent cannot silently change: product behavior, platform/stack, data ownership,
offline/online expectations, privacy/security needs, asset/dependency/budget constraints, and
accessibility requirements as applicable. Do not import another project's assumptions.

## Routine choices and scope changes

Agents select routine details in feature plans; implementation requests authorize those choices.
Record defaults and tradeoffs without separate approval for every name or tuning value. Material
changes to this brief require user direction. An optional CONTENT_CATALOG.md can track a finite
authored roster when the product actually needs one.

## Acceptance and limitations

Define observable functional, integration, rendering, data-integrity and release outcomes.
Agents supply evidence through the selected stack's verification profile. No required user
manual checks. Missing essential evidence prevents completion; subjective qualities that need
human observation remain explicitly unassessed and nonblocking. Do not use that distinction to
waive known defects. Packaging/deployment scope must be explicit; publishing requires authority.
