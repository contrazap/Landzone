# Feature plans

Use [FEATURE_PLAN_TEMPLATE.md](FEATURE_PLAN_TEMPLATE.md) for one on-demand plan per feature,
named F##_short_name.md. The [roadmap](../docs/ROADMAP.md) defines feature order and scope;
[PROGRESS.md](../PROGRESS.md) identifies the active plan and delivery.

- Inspect real code and baseline evidence before planning.
- Default to a single delivery implementing the entire feature.
- Split only at substantial integration or verification boundaries; explain why in the plan.
- "Implement the plan" executes the next delivery, including its internal implementation,
  integration, fixes, verification and documentation. Checklist items are not user gates.
- Select routine content details during planning. Implementation authorization covers the
  stated in-scope selections; future feature candidates remain unapproved.
- Map every required acceptance criterion to agent-obtainable evidence. Human playtests are
  optional feedback, never a prerequisite for completion or later planning.
- Keep exact outcomes, changed files, deviations and verification results in the plan.
- Do not generate later plans in advance or implement later roadmap features.
